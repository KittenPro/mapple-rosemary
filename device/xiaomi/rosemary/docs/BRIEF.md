Facts the vendor's open trees give for this phone, the gaps they leave, and the next steps. Generated by mapple-bringup;
nothing here has run on the phone. Each fact names where it was read (`file:line` of the tree, or the defconfig).

Inputs: Android device tree, kernel tree (overlay `rosemary.dts`, defconfig `rosemary_defconfig`), the phone's own tree, its GPT.

## Next steps

1. Run the probes below on the phone (Android, root), read only; share them with identifiers masked. Fill every empty value in `device.conf` and `adt.py` (each has a comment); mka stops on an empty required key and names it.
2. Make the GPT carve for `xnusys` (room: see storage facts) in files first; write it to the phone only on your word.
3. Boot with nothing of the phone's: loader banner and the kernel's first lines in pstore.
4. Memory: use the holes above; then storage read-only, display, touch, keys; then the rest, one boot-arg each, a risky step (voltage, clock, modem or SCP power, storage write) alone in its boot.

## Read-only probes (Android, root)

- soc: the cores' real part numbers (dts and BoardConfig disagree)
  ```
  adb shell su -c 'for i in 0 1 2 3 4 5 6 7; do cat /sys/devices/system/cpu/cpu$i/regs/identification/midr_el1; done'
  ```
- soc: what LK passes (lcm=, ramoops, bootopt); keep out serials before sharing
  ```
  adb shell cat /proc/cmdline | tr ' ' '\n' | grep -v -e serial -e imei
  ```
- memory: where Android placed the runtime pools (wifi, consys, ssmr, scp)
  ```
  adb shell su -c 'cat /proc/iomem'
  ```
- display: panel name and the layer LK leaves on
  ```
  adb shell su -c 'cat /proc/devinfo/lcd /sys/kernel/debug/dispsys/* 2>/dev/null'
  ```
- touch: which controller answers and its firmware version
  ```
  adb shell su -c 'cat /proc/touchpanel/* 2>/dev/null | head -50; ls /sys/bus/spi/devices'
  ```
- keys: the keys' scancodes
  ```
  adb shell getevent -lp | grep -B1 -A8 -i key
  ```
- pmic: rails and values Android runs with
  ```
  adb shell su -c 'cat /sys/kernel/debug/regulator/regulator_summary'
  ```
- battery: capacity, technology, voltage, charge counter
  ```
  adb shell su -c 'cat /sys/class/power_supply/battery/uevent'
  ```
- thermal: sensors and temperatures to compare against
  ```
  adb shell su -c 'for z in /sys/class/thermal/thermal_zone*; do echo $z $(cat $z/type) $(cat $z/temp); done'
  ```
- storage: the GPT (mask the disk and partition GUIDs before sharing)
  ```
  adb shell su -c 'dd if=/dev/block/sdc bs=4096 count=34 2>/dev/null' > gpt-head.bin
  ```
- gpu: OPP table and rails Android runs the GPU with (before any clock or voltage is set from our side)
  ```
  adb shell su -c 'cat /sys/kernel/debug/ged/hal/gpu_utilization /proc/gpufreq/gpufreq_opp_dump 2>/dev/null'
  ```
- wifi_bt: the firmware files and where the EMI pools were placed
  ```
  adb shell su -c 'ls -l /vendor/firmware /vendor/etc/firmware 2>/dev/null | head -60; cat /proc/iomem | grep -i -e consys -e wifi'
  ```
- sensor_hub: the SCP image Android loads and the sensor list it exposes
  ```
  adb shell su -c 'ls /sys/class/sensor* /vendor/firmware | head -40; dmesg | grep -i -e scp -e sensorhub | head -40'
  ```
- audio: card, codec and the mixer's default routes
  ```
  adb shell su -c 'cat /proc/asound/cards; cat /proc/asound/card0/codec#* 2>/dev/null | head -40; tinymix 2>/dev/null | head -80'
  ```
- camera: which sensors answered on this unit
  ```
  adb shell su -c 'dmesg | grep -i -e imgsensor -e seninf | head -60; cat /proc/kd_camera/* 2>/dev/null'
  ```
